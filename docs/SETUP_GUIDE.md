# Руководство по настройке — что требуется от заказчика

> Этот документ — ваша часть работы. Всё, что можно сделать без внешних ключей,
> я уже реализовал и протестировал. Здесь — **точные шаги**, что нужно настроить
> у себя, чтобы включить реальные функции.
> Правило: **все ключи подключаете вы через панель** (Подключения → Мастер API).
> Ключи хранятся зашифрованными на вашем сервере.

**Инструкция одна для всех:** запуск у заказчика и у разработчика ничем не отличается —
разница только в одном действии: после покупки заказчик вставляет **лицензионный ключ**
в панель (снимает демо-ограничения: водяной знак и лимит 3 ролика). Всё остальное — одинаково.

Время прохождения всех шагов: ~40–60 минут (разово), из них ~10 минут — установка и запуск.

---

## Установка и запуск системы (10 мин)

### 1.1. Что нужно (требования)

| | Минимум | Рекомендую |
|---|---|---|
| **Вариант Docker** (сервер) | Linux VPS 1 ГБ ОЗУ, 2 ГБ диска | 2 ГБ ОЗУ, 10 ГБ диска |
| Docker и Docker Compose | установлены | последние версии |
| **Вариант без Docker** (локально) | Python 3.11+, ffmpeg | Python 3.12, Node 18+ (для пересборки панели) |
| Интернет | есть | стабильный (нужен для озвучки, стоков, публикаций) |

> Заказчику достаточно **VPS от 500 ₽/мес** (любой: Timeweb, Beget, Selectel, Hetzner и т.п.).
> Если сервера нет — можно начать на своём ПК (вариант Б), а потом перенести.

### 1.2. Какие файлы нужны и где они лежат

Вся система — в репозитории **Content_fabric**. Основные части:

| Путь | Что это | Кому нужно |
|---|---|---|
| `backend/` | Серверная часть (FastAPI + SQLite). Код пайплайна, провайдеров, API | всем |
| `frontend/` | Веб-панель (React). Собирается в `frontend/dist/` и раздаётся сервером | всем (собирается автоматически в Docker) |
| `deploy/` | Готовый запуск в Docker: `docker-compose.yml`, `Dockerfile`, `Caddyfile`, `.env.example` | всем |
| `tools/oauth/` | Скрипты получения токенов: `youtube_oauth.py`, `telegram_chat.py` | всем (шаги 2–3) |
| `tools/keygen/` | Выпуск лицензий | **только разработчик** (заказчику не нужен) |
| `docs/` | Документация: `PLAN.md`, `ARCHITECTURE.md`, `SETUP_GUIDE.md` (этот файл), `SELLING.md` | всем |
| `.env` | Секреты (пароль админа, ключи шифрования) | создаётся при установке из `.env.example` |

Папки, которые система создаёт **сама при первом запуске** (в Docker — внутри volume `cf_data`):

| Папка | Что лежит |
|---|---|
| `data/cf.db` | База данных (темы, задания, журнал, ключи) |
| `data/media/jobs/<id>/` | Рабочие файлы каждого задания (сценарий, озвучка, сегменты, готовый `video.mp4`) |
| `data/media/music/` | Ваша фоновая музыка (положите туда `.mp3` — см. Шаг 5) |

### 1.3. Как получить файлы

```bash
# Вариант 1 — git (рекомендую: так проще обновляться)
git clone https://github.com/Tkhn-one/Content_fabric.git
cd Content_fabric

# Вариант 2 — архив (если git не нужен)
# GitHub → репозиторий → Code → Download ZIP → распаковать
```

### 1.4. Вариант A — Docker (рекомендую для сервера)

```bash
# 1) Установить Docker (если ещё нет), на Ubuntu:
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER && newgrp docker

# 2) Настроить конфиг
cd deploy
cp .env.example .env
nano .env        # обязательно поменяйте CF_SECRET_KEY на длинную случайную строку
                 # и задайте свой пароль админа CF_ADMIN_PASSWORD

# 3) Запустить (первый раз — с флагом --build, дальше без него)
docker compose up -d --build

# 4) Проверить, что работает
docker compose ps          # app и caddy должны быть Up
docker compose logs app --tail 50
```

**Открыть панель:** `http://<IP-сервера>` → логин `admin` / пароль из `.env` (`CF_ADMIN_PASSWORD`).

> HTTPS: если есть домен — пропишите его в `deploy/Caddyfile` вместо `example.com`,
> Caddy сам выпустит SSL-сертификат.

**Обновление системы** (когда выйдет новая версия):
```bash
cd Content_fabric && git pull
cd deploy && docker compose up -d --build
```

**Бекап** (раз в неделю — на всякий случай):
```bash
docker compose exec app tar -czf /tmp/cf_data.tar.gz -C /app data
docker cp <container>:/tmp/cf_data.tar.gz ./cf_data_backup.tar.gz
# хранить архив отдельно от сервера
```

### 1.5. Вариант Б — запуск без Docker (локально / dev)

Подходит для тестов на своём ПК (Linux, macOS, Windows):

```bash
# 1) Python 3.11+ и ffmpeg
#    Ubuntu:  sudo apt install python3-venv ffmpeg fonts-dejavu-core
#    Windows:  установить Python с python.org, ffmpeg — winget install ffmpeg

# 2) Серверная часть
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt   # Windows: .venv\Scripts\pip install -r requirements.txt

# 3) Собрать веб-панель (один раз)
cd ../frontend
npm install
npm run build          # появится frontend/dist — сервер отдаёт её сам

# 4) Запустить
cd ../backend
CF_SECRET_KEY=dev-secret ../.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
# → http://localhost:8000 → admin / admin123 (или ваш CF_ADMIN_PASSWORD)
```

> Для разработки панели с горячей перезагрузкой: в `frontend/` запустите `npm run dev`
> (Vite на порту 5173, сам проксирует запросы к API на 8000).

### 1.6. Первый вход и проверка (5 мин)

1. Откройте панель, войдите `admin` / пароль из `.env`.
2. **Подключения** → посмотрите статус «ДЕМО-РЕЖИМ» (водяной знак, до 3 роликов) —
   это нормально до активации лицензии.
3. **Темы и расписание** → создайте тему «Факты о космосе» → нажмите «Сгенерировать сейчас».
4. Откройте **Задания** → через ~20–40 секунд задание встанет в статус «Модерация»,
   в деталях — сценарий и готовое видео (без интернета фоны будут градиентами, без озвучки —
   это нормально для первого теста).
5. Если видео не собралось — см. раздел «Частые проблемы» ниже.

### 1.7. Частые проблемы при запуске

| Симптом | Причина | Решение |
|---|---|---|
| `озвучка пропущена: Cannot connect to host speech.platform.bing.com` | нет доступа к серверу озвучки | открыть исходящий 443; проверить интернет |
| `ffmpeg не установлен` | в dev-режиме нет ffmpeg | `sudo apt install ffmpeg` (в Docker он уже есть) |
| Панель открывается, но пустая страница | не собрана веб-панель | `cd frontend && npm install && npm run build` |
| `docker compose` не найден | старый Docker | установить Docker Compose v2 (`docker compose version`) |
| Водяной знак и «ДЕМО-РЕЖИМ» | лицензия не активирована | вставить ключ: Подключения → Лицензия (после покупки) |

## Шаг 1. Pexels — стоковые кадры (2 мин, бесплатно)

1. Откройте https://www.pexels.com/api/ → **Join / Get Started** (регистрация по email).
2. Создайте ключ: **Your API Key** → скопируйте строку вида `AbCdef...`.
3. В панели: **Подключения → Тип «stock» → Провайдер pexels** → вставьте ключ в `api_key` → Сохранить.

Теперь фоны роликов — реальные фото по теме (не градиенты). Без ключа система работает
на градиентах — это нормально для демо.

## Шаг 2. Telegram — публикация в канал (3 мин, бесплатно)

1. В Telegram: напишите **@BotFather** → `/newbot` → имя бота → имя-username → получите
   **bot_token** вида `123456789:AA...`.
2. Напишите вашему боту любое сообщение (`/start`).
3. Получите chat_id:
   ```bash
   cd tools/oauth
   pip install httpx            # если ещё нет
   python telegram_chat.py --token 123456789:AA...
   ```
   Скрипт напечатает `chat_id` (для канала — id с минусом, для чата — обычное число).
4. В панели: **Подключения → publish → telegram** → `bot_token` + `chat_id` → Сохранить.

## Шаг 3. YouTube Shorts — публикация и статистика (15 мин, бесплатно)

Это самый длинный шаг, делайте внимательно.

### 3.1. Проект Google Cloud
1. https://console.cloud.google.com → создать проект (например `content-factory`).
2. **APIs & Services → Library** → найти **YouTube Data API v3** → **Enable**.

### 3.2. OAuth consent screen
3. **APIs & Services → OAuth consent screen** → выбрать **External** → Create.
4. App name: `Content Factory`, ваш email → Save.
5. В разделе **Audience → Test users → Add users** → добавьте email своего канала (обязательно!).
   (В production-режиме Google запросит верификацию — для личного канала хватает Test-режима:
   100 тестовых пользователей, 7 дней жизни токенов, но refresh-токен не протухает.)

### 3.3. Клиент
6. **Credentials → Create Credentials → OAuth client ID → Desktop app** → Create.
7. Скопируйте **Client ID** и **Client Secret**.

### 3.4. Получить refresh_token (одноразово)
8. Запустите (на своей машине с Python):
   ```bash
   pip install httpx
   cd tools/oauth
   python youtube_oauth.py --client-id <CLIENT_ID> --client-secret <CLIENT_SECRET>
   ```
9. Откройте ссылку из консоли, войдите **каналом, куда будете публиковать**, нажмите Allow.
10. Скрипт напечатает `refresh_token` и `channel_id`.
    (Если браузер не открыл localhost — запустите с флагом `--manual` и вставьте code.)

### 3.5. Внести в панель
11. **Подключения → publish → youtube** → заполните: `client_id`, `client_secret`,
    `refresh_token`, `channel_id` → Сохранить.

> Важно: ключи принадлежат вашему Google-проекту. Квоты бесплатные (10 000 ед./день,
> загрузка ~100 ед. → десятки роликов в день).

## Шаг 4. Google Sheets + Drive — журнал и архив (10 мин, бесплатно)

### 4.1. Сервисный аккаунт
1. В том же проекте Google Cloud: **APIs & Services → Library** → включить
   **Google Sheets API** и **Google Drive API**.
2. **Credentials → Create credentials → Service account** → имя `cf-service` → Done.
3. В списке аккаунтов → нажмите на `cf-service` → вкладка **Keys → Add key → Create new key →
   JSON** → скачается файл `*.json` (это `service_account_json`, содержимое файла целиком).

### 4.2. Подготовить таблицу и папку
4. Создайте **Google-таблицу** (например «Content Factory»), переименуйте первый лист в `Журнал`,
   добавьте заголовки в строку 1: `Дата | Тема | Ниша | Заголовок | Платформы | Статус | Ссылка`.
   Скопируйте **ID таблицы** из URL (часть между `/d/` и `/edit`).
5. Поделитесь таблицей с email сервисного аккаунта (в правом верхнем углу таблицы «Доступ» →
   вставьте email из JSON, поле `client_email`) — роль **Редактор**.
6. Создайте **папку Google Drive** для архива роликов → скопируйте **ID папки** из URL.
   (Делать это нужно с того же аккаунта, что владеет проектом; папку тоже поделите с `client_email`.)

### 4.3. Внести в панель
7. **Подключения → storage → google_sheets** → `service_account_json` (вставьте ВЕСЬ JSON одной строкой)
   + `spreadsheet_id` → Сохранить.
8. **Подключения → storage → google_drive** → `service_account_json` + `folder_id` → Сохранить.

## Шаг 5. Фоновая музыка (2 мин, по желанию)

1. Создайте папку `data/media/music/` рядом с приложением (в Docker: `docker compose exec app mkdir -p /app/data/media/music`).
2. Положите туда 1–5 треков `.mp3` (royalty-free: YouTube Audio Library, Pixabay Music, Free Music Archive).
3. Система сама выберет случайный трек и **приглушит его под голосом** (ducking).

## Шаг 6 (Pro). Клон голоса и AI-аватар

Реализованы, ждут ключей (Pro-тариф).

### 6.1. ElevenLabs (качественный голос / клон голоса)
1. https://elevenlabs.io → регистрация → **Profile → API key** → скопировать.
2. Голос: в разделе **Voice Lab** → Create a new voice (или Instant Voice Cloning — загрузите
   образец голоса 1–3 мин) → получите `voice_id` (строка вида `21m00...`).
3. Панель: **Подключения → tts → elevenlabs** → `api_key` (+ при желании `voice_id` по умолчанию) → Сохранить.
4. В теме можно указать свой `voice_id` (поле «Голос») — он перекроет дефолтный.

### 6.2. HeyGen (говорящий AI-аватар)
1. https://heygen.com → регистрация → **API** → **API token** (или в настройках аккаунта) → ключ.
2. Аватар: в редакторе HeyGen выберите аватара → в URL/настройках найдите его `avatar_id`
   (например `Chris_public_...`) или возьмите из **Avatars API** (GET /v2/avatars).
3. Панель: **Подключения → avatar → heygen** → `api_key` (+ `avatar_id` по умолчанию) → Сохранить.
4. В теме укажите `avatar_id` (поле «AI-аватар») — ролик будет с говорящим аватаром.
   Голос аватара — из HeyGen (можно передать `voice_id` в настройках провайдера).

## Шаг 7 (Pro/Unlimited). TikTok, VK, Instagram Reels

Реализованы, ждут ключей.

### 7.1. TikTok (Pro+)
1. https://developers.tiktok.com → создать приложение → запросить scopes `video.publish`, `video.upload`
   (модерация приложения 3–7 дней; нужны privacy policy, демо-видео, описание).
2. После одобрения: получить `client_key` (app key), `client_secret`, и через OAuth — `access_token`
   + `refresh_token` (токены живут 24 ч, система обновляет их сама по refresh_token).
3. Панель: **Подключения → publish → tiktok** → заполнить 4 поля → Сохранить.

### 7.2. VK Clips (Unlimited)
1. https://vk.com/dev → создать приложение → включить права `video`, `wall`, `photos`.
2. Получить **токен сообщества**: https://vk.com/dev/access_token → «Токен сообщества»
   (выберите сообщество, права video+wall) → скопировать.
3. `group_id` — id сообщества (число из адреса vk.com/club12345).
4. Панель: **Подключения → publish → vk** → `access_token` + `group_id` → Сохранить.

### 7.3. Instagram Reels (Unlimited)
1. Business/Creator-аккаунт Instagram + **страница Facebook**, связанная с ним.
2. https://developers.facebook.com → приложение → продукт **Instagram Graph API** → подключить аккаунт.
3. Получить долгоживущий `access_token` и `user_id` (раздел «API Setup» в приложении).
4. **Нужен публичный адрес системы** (`server_url`, например `https://cf.example.com`) —
   Instagram принимает только публичные URL видео.
5. Панель: **Подключения → publish → instagram** → `access_token`, `user_id`, `server_url` → Сохранить.
